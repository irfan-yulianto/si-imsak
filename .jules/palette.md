## 2024-06-05 - Added XIcon to Icons
**Learning:** Adding an absolute positioned clear button (e.g., an `XIcon`) inside search inputs that conditionally renders when the query length is > 0 is a standard micro-UX pattern. Ensure to add adequate right padding (e.g., `pr-9`) to the input to prevent text overlap, conditionally hide the button during loading states (e.g., `isSearching`) to avoid layout collisions, and use `aria-label` with keyboard-friendly interactions (returning focus to the input upon clearing). The application's primary language is Indonesian. When adding user-facing text, ARIA labels, or tooltips (e.g., 'Hapus pencarian' untuk clear button), ensure they are localized appropriately rather than using English defaults.
**Action:** Always verify if a close/clear action makes sense in search inputs and implement it with the proper localized `aria-label` and focus management. Avoid using DOM queries, use `useRef` where appropriate, though direct DOM queries via `document.querySelector` can act as a fallback. Reused `XIcon` from the `Icons` library.
## 2024-06-05 - Avoid Direct DOM Queries
**Learning:** Directly querying the DOM to restore focus using `document.querySelector` is an anti-pattern in React. Wait to receive PR feedback before assuming temporary hacks will pass code review.
**Action:** Use `useRef` to maintain references to input elements within React components. Call `.focus()` on `ref.current` instead of querying the DOM when building keyboard-accessible clear buttons.
