## 2025-02-12 - Identifying Unnecessary Re-renders
**Learning:** `TodayCard.tsx` consumes `useCityMinute()` directly. `useCityMinute()` updates its value every minute, which triggers a full re-render of `TodayCard` and all its child components every single minute. The only part of the UI that actually needs to change based on the current minute is `currentPrayerIdx` (which prayer is currently active). Since there are only 8 prayers a day, `currentPrayerIdx` only changes 8 times a day.
**Action:** By extracting the logic that calculates `currentPrayerIdx` into its own subscription (or a new hook `useCurrentPrayerIdx`) that only returns a new value when the active prayer changes, we can prevent 1432 unnecessary re-renders per day for the `TodayCard`. Wait, we can modify `useCityClock.ts` to expose `useCurrentPrayerIdx(prayerMinutes: number[])`. But it uses `subscribeToClock`. We can just write a custom `useSyncExternalStore` in `TodayCard` (or `hooks/useCityClock`) that returns the `currentPrayerIdx` directly!

### Action for TodayCard re-renders
By verifying through a benchmark test, `TodayCard` currently re-renders every single minute due to `useCityMinute()`, updating 12 times in 11 minutes (including initial load). Since the component only needs to know the index of the currently active prayer, we can optimize this by exposing a `useCurrentPrayerIdx(prayerMinutes)` hook that subscribes to the clock but maps the time to the index before returning, preventing ~1432 redundant re-renders per day.
